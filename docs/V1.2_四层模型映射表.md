# EDP V1.2 四层数据模型 ↔ 现有表映射表（T04 交付物）

**配套方案：** V1.2 第十六节（V1.1 第三十三节增补）  
**盘点基数：** 51 张业务表（W1 基线 49 张 + W4 `audit.policies` + W5 `ops.tasks`），迁移 0001~0013  
**原则：** RAW 不可覆盖；只有 CURATED/OFFICIAL 可被 EBMS/Agent/Metric/Result/Decision/Action/Value 消费

---

## 一、四层定义速览

| 层 | 含义 | 载体（改造后） |
| --- | --- | --- |
| RAW | 源系统原始数据，永久不可改 | `raw_records` 新表（T08） |
| CLEAN | 清洗后的版本（不得覆盖 RAW，只产生新版本） | 清洗留痕表 + 清洗版本引用（T09） |
| STANDARD | 统一编码/单位/主数据映射后的标准数据 | 现有 `master.*` + 领域投影表（现状定位） |
| CURATED / OFFICIAL | 完成分类/审核后的正式企业事实 | admission 状态 + `official_version` 指针 + 归档（T15/T19） |

## 四、现有 ingest 管道改造清单（T08 前置）

现状：`adapter → SourceRecord → ingest 单事务（对象 upsert → 领域投影 savepoint → SNAPSHOT 事件 → 证据 → outbox）`，无 RAW 留存。

改造后：

```text
adapter.fetch → raw_records 落库（先留存，含 checksum/batch_id）
              → profiling（T09/T16）
              → cleaning rules 执行（留痕 clean_records）
              → 领域投影（现有逻辑，savepoint 隔离不变）
              → admission 状态推进（RECEIVED→…→OFFICIAL/ARCHIVED，T15）
              → lineage 记录（T20）
```

约束：现有"逐记录独立事务 + UUIDv5 幂等 + 水位推进 + reconcile 三计数"机制全部保留，RAW 落库进入同一事务。
