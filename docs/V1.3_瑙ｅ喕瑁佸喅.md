## 一、解冻内容与边界

| 项 | 裁决 | 说明 |
| --- | --- | --- |
| Kafka | ✅ 解冻（受限） | 仅承载 Debezium CDC 变更事件 topic（命名规范 `edp.{tenant}.{system}.{table}`），不做通用消息总线、不做业务事件通道（业务事件仍走 Outbox） |
| Debezium Connector | ✅ 解冻（受限） | 首期 PostgreSQL Connector（pgoutput）；MySQL / SQL Server Connector 为预留扩展（仅配置差异） |
| Lakehouse | ❌ 维持冻结 | — |

| Flink 等实时计算平台 | ❌ 维持冻结 | 消费侧为 aiokafka 常驻协程（worker 进程内），不引入流计算 |
| 向量集群 / 重型 MDM | ❌ 维持冻结 | — |

## 二、解冻理由

1. 供应链系统为自研系统（PostgreSQL），核心业务对象（订单/库存/工单/物料）存在分钟级以内实时入库诉求；
2. 高频直连生产库轮询 SQL 与"不打扰源系统"原则冲突（V1.2 行动计划风险表同源结论）；
3. 拉取轨（fetch_incremental 增量水位）对高频变更场景延迟与源库压力均不可接受；
4. Outbox 分发接缝（订阅者 `on_event(event) -> ack/nack`）为出向事件预留，**不覆盖**入向实时采集——入向缺口只能由 CDC 补齐。

## 四、蔓延防线（回退条款）

- 解冻仅限本表范围；任何超出（Flink / Lakehouse / Kafka 承载业务消息）须重新裁决；
- CDC 事件必须走 RAW → A1–A4 管道，禁止直写 STANDARD / OFFICIAL（停止事项 17）；
- 为 CDC 不得另建质量/对账/监控系统（复用 quality + ops.tasks + health，停止事项 18）；
- 源库负载超标或 slot 积压处置不力 → G5 门禁不过 → 暂停实时轨、回退拉取轨兜底。
