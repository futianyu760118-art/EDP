**Files:**

- `backend/tests/integration/test_events_api.py`（前缀参数用例扩展——文件名以既有事件测试实际路径为准）

**实现：**
- `GET /api/v1/search?q=&limit=`：q 必填（trim 后 ≥1 字符），limit 默认 10 上限 50（每组上限）；
- 三组聚合（同事务三查询，RLS 自然过滤）：
  - objects：registry 对象表 `source_id/object_type` ILIKE `%q%`（attrs 不参与——JSONB 全扫成本，docstring 留痕）；
  - events：`event_type` ILIKE 或 `data->>'summary'` ILIKE（按 events 模型实际列定）；
  - evidence：`ref/kind` ILIKE；
  - 每组按 created_at DESC LIMIT limit；响应 `{query, objects[], events[], evidence[], total}`（total=三组返回行数合计；投影最小字段：id + 各自主显示字段 + object_type/event_type/kind）；
- events 前缀参数：`event_type_prefix`（LIKE `prefix%`）；与 `event_type` 同传 → 422（RequestValidationError 手动抛，detail 注明互斥）；service 过滤链 `query_events` 增对应条件；
- 空 q 结果 → 三空数组 + total 0（前端空态依据）。

**测试：** seed 后按已知 source_id 片段/event_type 前缀/证据 ref 检索——三组各命中 + 跨租户 0 行 + limit 截断 + 空 q 空数组；events `event_type_prefix=quality.` 命中前缀事件 + 双参数同传 422 + 既有精确匹配用例不破。

**Verify:** `& "backend\.venv\Scripts\python.exe" -m pytest tests/integration/test_search_api.py tests/integration/test_events_api.py -q` + ruff + lint-imports

**实现：**
- `seed [--reset] [--scale N]`（默认 1=现有十类场景基线）：N>1 时在基线外追加放大实体——对象/事件/证据按确定性后缀（如 `source_id := f"{base}-{i:05d}"`）×N 生成，UUIDv5 幂等保重放复位语义不变；十类场景本体不放大（评估与召回统计基于基线场景）；
- 目标量级校准：`--scale` 使全库 ≈5k 对象 / 50k 事件 / 10k 证据（N 按 dataset 基数换算，实测写入 docstring）；分批写入（每批 ≤2k 事件防单事务过大）；
- 覆盖率/召回统计不受放大影响（放大实体标记 `attrs.scale=true` 或独立 object_type 前缀——覆盖率分母排除，实现取最小：放大对象不注册进 coverage 统计口径的「已接入」分子分母即可，docstring 留痕）。

**测试：** `--scale 3` 后三类计数 = 基线×(1+2) 断言（SQL 计数）；重跑同 scale 计数不变（幂等）；`--reset` 复位。

**Verify:** `& "backend\.venv\Scripts\python.exe" -m pytest tests/integration/test_demo_seed_scale.py -q`
