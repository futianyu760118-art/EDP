## 一、系统边界

```text
M01 AEOS Kernel   权限 / Goal 定义 / KPI 口径 / Policy / Constraint / Guard / Agent 中枢
M02 EDP           Object 引用 / Event / Result / Evidence / Audit / Metric 记录 / Value / Trace
M03 EBMS          经营结果与决策工作面（只读 Result / Metric / Exception / Decision / Action / Evidence）
M04–M09 自治中心   各自域内业务事实生产（销售/研发/交付/品质/财经）
```

冻结条款：

| # | 条款 | 判定 |
| --- | --- | --- |
| B-01 | EDP 不替代 ERP / MES / CRM / PLM，不实现其业务功能 | 冻结 |
| B-02 | EDP 不是第二套 EBMS，不做经营驾驶舱 | 冻结 |
| B-03 | EDP 不是 Agent Runtime，不承载 Agent 决策逻辑 | 冻结 |
| B-04 | 跨系统交互统一经 API / Event / Result / Evidence，禁止跨域直接写表 | 冻结 |
| B-05 | EBMS 只读 Result / Metric / Exception / Decision / Action / Evidence，禁止直查业务表 | 冻结 |
| B-06 | Agent 只能经 Tool API（Guard 保护）访问 EDP，禁止自由 SQL / 直接 DB 写 | 冻结 |
| B-07 | EDP 只存 Decision Record / Action Record，决策规则、审批、Guard 归 M01/DEH | 冻结 |
| B-08 | EDP 不实现审批流引擎；A2/A3 审核工作台只存审核任务与审核记录 | 冻结（V1.2 新增） |
| B-09 | EDP 不新增目标管理、指标口径决策功能 | 冻结（V1.2 新增） |

## 二、数据 Owner 基线

| 数据/事实 | 正式 Owner |
| --- | --- |
| Person / Organization / Position | M01 AEOS Kernel |
| Customer / Lead / Inquiry / Quote / Order 商务事实 | M05 Sales |
| Product / Requirement / BOM / ECO | M04 R&D |
| 交付执行事实 | M06 Delivery |
| Quality 事实 | M08 Quality |
| Revenue / Cost / Cash / AR/AP | M09 Finance |
| Event / Evidence / Audit / Result / Value Ledger | **M02 EDP** |

冻结条款：

| # | 条款 |
| --- | --- |
| O-01 | EDP 保存标识 + 必要事实 + 引用 + 快照 + 证据，不复制业务系统全部字段 |
| O-02 | 专业业务事实的 Owner 是所属自治中心，EDP 只做事实底座，不抢业务所有权 |
| O-03 | 任何 Result 引用对象的数据源变更须经 Owner 域确认，EDP 不裁决业务口径 |

## 三、Goal / KPI / Constraint 边界（响应核准报告第十一节）

```text
M01 AEOS Kernel
├─ Goal 定义与目标值（target）
├─ KPI 口径定义（formula 的决策方）
├─ Policy / Constraint
└─ 口径争议裁决
        ↓ 下发快照
M02 EDP
├─ Goal Snapshot（记录，只读引用）
├─ KPI Value（计量值）
├─ Metric 注册表（记录版：注册、版本、公式快照）
├─ Result / Evidence / 历史状态
```

冻结条款：

| # | 条款 |
| --- | --- |
| G-01 | 规则归 Kernel，事实归 EDP；EDP 不产生口径决策 |
| G-02 | Metric 定义的 definition_owner 为业务域；target_owner 为 M01；EDP 仅注册与记录 |
| G-03 | 口径变更必须由 definition_owner 发起、版本化、留审计，EDP 不裁决 |
| G-04 | EBMS 目标看板所需目标值，第一阶段以"M01 下发快照 / 域 Owner 录入并标注 owner"方式进入 EDP，来源必须可追溯 |

## 四、现有 `management.*` 表处置策略

现状（迁移 0004）：`objectives / kpi_definitions / kpi_values / constraints` 已建在 EDP，demo seed 灌数，ebms 模块只读查询。

| 表 | 现状用途 | 处置策略 | 时点 |
| --- | --- | --- | --- |
| objectives | 经营目标（target_value 目标值在内） | 保留为 **Goal Snapshot**：加 `owner`、`source`（M01_SNAPSHOT / DOMAIN_ENTRY）字段；目标值语义标注为快照，不产生新目标管理功能 | T23 迁移时同步 |
| kpi_definitions | KPI 定义（code/name/formula/unit） | 迁移入 **Metric Registry**：加 definition_owner / definition_source / target_owner / version / effective_from / effective_to；formula 标注为注册快照 | T23 迁移时同步 |
| kpi_values | KPI 期值 | 并入 Metric 计量值：加 period_rule 引用；ebms 只读查询保留 | T23 迁移时同步 |
| constraints | 硬性约束（与 Guard 联动） | 归属 M01（Constraint 定义），EDP 保留表但冻结新增写入入口，等待 M01 接管；存量数据只读 | T01 冻结后立即 |

**红线：** 在 M01 接管前，EDP 任何人不得在上述表中新增"口径决策"类数据；T23 迁移前不得删除上述表。
