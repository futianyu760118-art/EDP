# EDP V1.2 数据准入状态机 A1–A4 设计（T05 交付物）

**配套契约：** `contracts/governance/admission-state.schema.json`（T02 已冻结）  
**对应任务：** T15（admission 模块落地）、T13/T14（A2/A3 审核）  
**边界红线：** EDP 只存审核任务与审核记录，不实现审批流引擎（V1.2 B-08）

---

## 一、状态机总览

```text
A1 原始留存      RECEIVED
A2 本系统共审    PROFILED → CLEANED → STANDARDIZED → CLASSIFIED
                → SOURCE_REVIEW ─┬─ SOURCE_APPROVED → (A3)
                                 ├─ REJECTED / RETURNED / SUSPENDED / ESCALATED
A3 管理复审      MANAGEMENT_REVIEW ─┬─ MANAGEMENT_APPROVED → OFFICIAL
                                   ├─ REJECTED / RETURNED / SUSPENDED / ESCALATED
A4 归档          OFFICIAL → ARCHIVED
```

完整 15 态与转移表见契约 `admission-state.schema.json` 的 `definitions.transitions`。

**硬约束：**
1. 任何状态变化必须产生 Event + Audit（V1.1 第四十四节）；
2. 只有 `MANAGEMENT_APPROVED` 才允许转 `OFFICIAL`；
3. 只有 `SOURCE_APPROVED` 才允许进入 `MANAGEMENT_REVIEW`；
4. 只有 `OFFICIAL/ARCHIVED` 数据可被 EBMS / Agent / Metric / Result / Decision / Action / Value 消费。

## 二、迁移草案（T15）

```text
schema governance

governance.admission_records
    admission_id        UUID PK
    tenant_id           UUID NOT NULL REFERENCES platform.tenants
    object_id           UUID NOT NULL REFERENCES master.business_objects
    state               TEXT NOT NULL  -- 15 态枚举，CHECK 约束
    review_result       TEXT NULL      -- 六结果枚举（APPROVED / APPROVED_WITH_WARNING /
                                       -- RETURN_FOR_CORRECTION / REJECTED / SUSPENDED / ESCALATED）
    quality_score       NUMERIC(5,2) NULL
    machine_result      JSONB NULL     -- 机器预审/复审输出（PASS/WARNING/FAIL + exception_list + suggested_fix）
    source_human_reviewer   TEXT NULL  -- A2 人工审核人
    source_reviewed_at      TIMESTAMPTZ NULL
    management_human_reviewer TEXT NULL  -- A3 人工确认人
    management_reviewed_at    TIMESTAMPTZ NULL
    archived_at          TIMESTAMPTZ NULL
    raw_version / clean_version / standard_version / classification_version  TEXT NULL
    dimensions / classifications / tags   JSONB NULL
    evidence_refs        UUID[] NOT NULL DEFAULT '{}'
    checksum             TEXT NULL
    version              INT NOT NULL DEFAULT 1   -- 准入记录版本（乐观锁）
    created_at / updated_at  TIMESTAMPTZ
    UNIQUE (tenant_id, object_id, version)？—— 见注 1
    RLS：tenant_id = app.tenant_id（沿用仓库惯例）
```

注 1：一个对象一次准入周期一条记录（version 用于退回修正后的重审周期）；唯一约束 `(tenant_id, object_id)` 在 RETENTION 前的重审用同记录推进，实现时以迁移评审裁定。

## 三、审核记录模型（A2 / A3 共用结构）

```text
review_ref（id）
 ├─ admission_id        -- 归属准入记录
 ├─ stage               -- SOURCE_REVIEW | MANAGEMENT_REVIEW
 ├─ machine_result      -- 机器检查输出（见第四节）
 ├─ human_decision      -- 六结果枚举
 ├─ human_reviewer      -- 责任人
 ├─ comment             -- 审核意见（留痕）
 ├─ reviewed_at
 └─ evidence_refs       -- 审核依据
```

## 四、机器检查规则（两级分工，不得互相重复）

| 阶段 | 机器检查项（V1.1 第四十/四十一节） |
| --- | --- |
| A2 本系统预审 | 完整性、格式、字段类型、重复、异常值、业务规则、主数据匹配、分类与标签、数据质量分数 |
| A3 管理系统复审 | 跨系统一致性、指标口径一致性、时间窗口一致性、Business Object 关联、跨域冲突、Evidence 完整性、历史合理性、经营规则、权限与合规 |

A2 输出：`PASS / WARNING / FAIL + quality_score + confidence + exception_list + suggested_fix`。
A3 判定的是"该数据是否有资格成为企业正式事实"。

## 五、人工审核策略（V1.2 治理分期，第一阶段）

```text
A2：机器审全量 + 人工抽检（抽检比例随 T13 定稿，异常/WARNING 记录必抽）
A3：关键对象人工确认（Customer/Product/Material/Order 首链路对象）
```

## 六、执行者说明（V1.2 第十六节增补）

- 自治中心 M05–M09 建成前，A2/A3 由 **EDP 轻量审核工作台**承载：审核人以域 Owner / 管理角色账号操作；
- EDP 只保存"审核任务 + 审核记录 + 状态推进"，不实现会签/转办/超时升级等审批流功能；
- 自治中心建成后，A2 由对应中心接管，EDP 接口不变（记录层不动）。

## 七、事件与审计约定

```text
状态推进事件：governance.admission.<State>（如 governance.admission.SOURCE_APPROVED）
审核动作审计：AUDIT_ADMISSION_REVIEW（stage / decision / reviewer 入审计日志）
数据质量阻断：低于门禁产生 DataQuality.Exception（T16），不推进状态
```

## 八、与 T19 / T20 的衔接

```text
MANAGEMENT_APPROVED → business_objects.official_version 写入 + lineage 收口（official_version）
ARCHIVED           → 归档字段回填（archived_at / checksum / dimensions / classifications / tags）
RETURNED           → 对象回 CLEANED/STANDARDIZED/CLASSIFIED 对应环节，version +1 重审
```
